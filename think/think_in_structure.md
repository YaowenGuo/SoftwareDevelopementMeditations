# 架构所想

从无架构 到 MVP -> MVVM -> MVI 

数据 Model 没变，UI View 没变，变化的之有两者之间的操作关系。架构一直在关注两者如何关联之上，但我想说的是。Model 才是比它们更应该关注的点。

我们首先应该考虑的就应该是 数据的组织。
数据应该清晰的反应他们之间的关系。
             更新 UI ->
Model    <==================> View 
            <--- 操作数据

数据结构决定了是否容易理解
抽象能力决定了是否好用
算法决定了程序是否高效

后台返回的数据也不一定是有很好结构的，例子就是首页的做题分类tab, 不能反映出 CourseSet、Course 之间的关系。

Binder 的开发者技术能力很强，但是抽象能力就差点意思。Binder 的接口就比较难用。

都叫 Binder 粘合剂了，为什么所有的类要继承 Binder。 不能是是 XXXApi service = Binder.bond(XXX) 粘合一下吗？或者 XXXApi service = XXXApi.bound()。

声明式 UI 开启了编写 UI 的新篇章，让我们从该如何组织 UI，到只需要关心什么样的数据应该是什么样的 UI，大大减轻了心智负担。
