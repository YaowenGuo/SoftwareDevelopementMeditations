# 检查

通过检查性能，你可以了解应用程序中发生了什么，并确保它符合你的期望。

Android提供了几个工具，你可以用来检查你的应用程序的性能。在开始时，我们建议您在检查期间一次只关注一个方面。

这些领域包括：
- 应用启动
    Macrobenchmark library
    Macrobenchmark 
- 渲染缓慢（jank）
- 屏幕过渡和导航事件
- 长期运行的工作
- 背景中的操作，例如I/O和网络

或者，您可以检查应用程序工作流的关键用户流程。这可以帮助你全面了解性能和预期不一致的地方。

检查性能有两种主要方法，手动和自动。在检查一个新领域时，很可能从手动调试开始。


性能是对资源利用的另一个视角审查：对性能的本质其实是对资源的利用，这些资源包括硬件资源： CPU、内存、电量、网络 以及软件资源（操作系统系统资源）线程数量、文件描述符、网络连接数量。其中软件资源的本质也是硬件资源，其是对应用可使用硬件资源的进一步限制。例如线程的数量限制本质是对可使用内存的限制。文件描述符也是对内存和 IO 资源的限制。


解决性能问题涉及确定您的应用程序使CPU，内存，图形，网络或设备电池等资源效率低下的领域。

## 手动

在决定要检查应用的哪个区域之后，你可以使用各种工具来确定到底发生了什么。最全面的检查 Android M(6)及以后设备性能的工具是[Perfetto](https://perfetto.dev/)。Perfetto为您提供尽可能详细的跟踪信息。通过使用强大的过滤器，您可以根据需要调整细节级别。有关如何从Android设备捕获跟踪的详细信息，请参阅快速入门:[在Android上记录跟踪指南](https://perfetto.dev/docs/quickstart/android-tracing)。

最新的 Android Studio 内置的 Android profiler 也是基于 Android Perfetto 的采集技术，额外加了安卓框架中收集的数据。Android Studio Profiler 由于封装可能限制更多的自定义选项，而 Perfetto 则更灵活，您可以根据需要选择使用哪种。




## 自动

除了手动检查之外，您还可以设置自动测试来收集和聚合性能数据。这有助于您了解用户实际看到的内容，并确定何时可能出现回归。有关为应用程序设置自动性能测试的更多信息，请参阅对应用程序进行[基准测试]()。


## 各种剖析工具适用场景

System traces：
- 包含进程、线程、时序信息、CPU 和任务执行，以及系统或用户定义事件的信息
- 从应用的角度来看，追踪信息的性质可以涵盖延迟、卡顿、内存、电池续航等多个领域。

- PerfettoSQL 查询创建的指标，可用于进行分析或比较跟踪

- 跟踪具体资源的使用情况和时序关系。例如 CPU 使用率、内存使用率、网络使用率、电池使用率等。


适用场景：
- 诊断延迟问题。 系统跟踪对于发现因延迟、等待或调度问题引起的延迟问题非常出色。其他分析器，如基于样本的剖面，则无法提供系统跟踪所提供的时序信息。
- 查找重复的计算。 追踪可以揭示某些计算是否被重复，这可能表明作是不必要的。
- 诊断锁争用问题。 通过线程状态和切片信息显示资源被阻塞，你可以识别锁（如同步块）是否导致用户旅程延迟。
- 了解你应用中的多线程。Traces 可以查看多个线程，显示每个线程的状态以及系统或你的应用添加的任何 trace 片。这种多线程视图帮助你了解哪些线程处于活跃状态、处于休眠状态，或者它们运行了什么，以及它们如何相互作用。

- 进行复杂的性能分析。 强大的用户界面和显示各种信息的能力使系统跟踪在调试各种性能问题时非常有用，包括延迟、内存和电池使用。


CallStack sample (Profiles)

记录代码的执行采样、以固定速率存储CPU上线程调用栈信息。帮助分析代码执行中的行为。

适用：

- 优化热点。 栈示例有助于识别代码中 CPU 活动较多的部分，意味着线程通常处于“运行”状态。
- 理解代码执行。 栈采样可以帮助你理解代码的整体行为。
- 识别不应该运行的代码。 帮助发现不改执行的代码。

Heap dumps:

heap dumps 是应用堆内存的快照，帮助分析内存使用情况。包含转储是的所有数据对象及其的关系。

适用：

- 发现重复对象： 堆转储显示了活跃对象的数量，这对于追踪重复对象非常有用。它们还提供对象引用，帮助你精确定位代码创建对象的位置。

- 找出内存泄漏。 堆转储可以揭示转储时不应再使用的内存，提示潜在的内存泄漏。

- 识别可以优化的对象。 堆转储通过展示内存的对象及其计数，有助于识别低效的内存使用方式。

Heap profiles：

堆配置剖析工具有原生和 Java 两种，非常适合调试内存问题。它们类似于调用栈采样，只是用于内存分配时采样。

适用：

- 减少内存流失。 堆剖析展示了内存分配的代码位置。这便于你识别产生许多临时对象的区域，这些对象可能导致应用中频繁的垃圾回收（GCs）。
- 发现内存泄漏。 堆剖析可以与其他内存剖析一起使用，用于诊断和修复内存泄漏。它们帮助你精准定位那些内存分配远超预期的位置。

在实际应用中可能需要多种剖析工具结合使用，以便高效的定位问题。

- 情景一：调查未执行的代码。 系统跟踪显示了程序运行时执行的操作。有时，你可能需要那些时间段运行未执行代码的信息。为了调查，获取 stack profile 来理解代码的执行。它能提供额外的补充信息来帮助优化追踪。

情景二：分析内存泄漏和垃圾回收。 想象系统跟踪显示由于 Java 内存分配导致堆持续增加，触发频繁的垃圾回收（GC）。要了解分配的对象，可以取一个堆剖析或堆转储。结合多种工具能帮助你找到减少内存使用的方法。例如，利用缓存来减少内存浪费或优化分配，避免垃圾回收的发生。


## 收集 Profile 方式

- 外部工具：Perfetto 或者 Android Studio Profiler
- ProfilingManager （安卓 API）: 让应用程序在生产环境中收集配置文件。

ProfilingManager 来收集和分析大量用户的数据调试罕见问题。而对于更容易复现的问题，外部工具是更好的选择。

ProfilingManager 生成的是经过删减的数据。而且只显示自己应用流程的信息，隐藏了系统中其他应用的数据。由于 ProfilingManager 会收集并删减后再返回，你可以从公开用户那里收集数据，同时不显示来自其他应用的数据因此保护他们的隐私，。

ProfilingManager can also collect profiles when specific events happen, such as an Application Not Responding (ANR) error or app startup. ProfilingManager will handle the starting and stopping of profiles for event-based collection.
